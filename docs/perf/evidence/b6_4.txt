4. EXPLANATION OF BUG IN PREVIOUS B1/B1.5 REPORT (Total evaluated < entered + left)
--------------------------------------------------------------------------------
In scripts/analyze_b1_mechanisms.py line 118-122, the tie count was calculated as:
  all_res_book = res.get('results', {}).get(book, [])
  total_tied_pool = sum(1 for x in all_res_book if x['scores']['final'] == score_10th)
Bug Explanation:
  res['results'][book] is ALREADY sliced to top_k=10 by finalize() (return unique[:top_k]).
  Inspecting res['results'][book] only counts ties among the 10 returned candidates,
  completely missing the candidates in the pool that were truncated beyond rank 10.
Consequence:
  - church Noli:    Reported ties = 9.  Actual ties in pool = 23 (pool size 28).
  - Basilio El Fili: Reported ties = 10. Actual ties in pool = 27 (pool size 115).
  - death El Fili:   Reported ties = 10. Actual ties in pool = 16 (pool size 25).
  - education El Fili: Reported ties = 7. Actual ties in pool = 21 (pool size 24).
All earlier figures reporting 'Total evaluated candidates' were capped at 10 due to this slice bug.
The recomputed table in Section 3 provides the true pool statistics directly from finalize().
